AI AGENT 導入指南 · 工作流程評估

哪些工作適合導入 AI Agent？

先找出一項值得試做的工作，比先選模型或工具更有用。以下四個問題，可用來判斷流程是否具備導入條件。

Michael Agent Lab · 實務判斷指南

先看工作是否能被描述清楚

適合起步的任務通常反覆出現，輸入資料和預期輸出可以說明，也能指出哪些步驟需要人判斷。例如定期整理文件、比對版本差異、彙整待辦與追蹤狀態。這些是可能的試做情境，仍需逐項確認資料與規則。

若每次目標都不同、資料來源不固定，或完成與否只能靠高度主觀的判斷，先整理工作方式通常比直接建 Agent 更有效。

用四個問題篩選第一項流程

1. 這項工作是否重複，規則能否說明？

記下觸發時機、輸入、處理步驟與輸出。若同樣的判斷每次都要重新討論，先把例外情況列出來。

2. 資料在哪裡，誰可以使用？

列出文件、系統與存取權限；確認資料能否交給所選工具處理。敏感資料若不能離開既有環境，應先評估本機或自架方案的可行性。

3. 哪些地方必須由人確認？

把不可逆的動作、對外發送與重要決策設成確認點。Agent 可準備資料與建議，但需要明確知道何時停下來。

4. 怎麼知道試做成功？

挑幾個實際案例，先寫好預期結果與錯誤條件。驗收時看輸出是否正確、例外是否被標出、同事能否按說明重跑，而不只看一次順利的示範。

一個小範圍試做的例子

以「每週彙整專案進度」為例，可以先限定輸入為指定資料來源，輸出為待辦、阻礙與需要人工確認的事項。Agent 負責整理與標示缺漏；負責人確認後，才將內容發給團隊。

這是說明評估方法的示例，不代表已完成的客戶專案。實際方案會依資料環境、權限與交付要求調整。

想先看實際成果？可到分類作品集，查看學習 App、工作工具、遊戲與網站展示。每件作品都有畫面與完成狀態。

下一步怎麼開始

  1. 選一項每週或每月都會做、結果可以檢查的工作。
  2. 準備一份目前做法與兩三個真實例子，隱去不必要的敏感資料。
  3. 先確認資料、責任人與驗收方式，再決定工具和試做範圍。
