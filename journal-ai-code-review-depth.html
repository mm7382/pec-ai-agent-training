AI 寫的 Code，到底還要不要逐行讀？

一次性工具、產品功能與安全關鍵路徑，不該使用完全相同的審查方式。

兩種看似相反的答案

AI Agent 幾分鐘就能寫完一個功能，人可能還在看第一個 diff。Mitchell Hashimoto 強調工程師應該閱讀並理解自己部署的程式碼；Robert C. Martin（Uncle Bob）則更重視清楚需求、測試、mutation testing 與 QA 所建立的驗證證據，而不一定逐行閱讀。

我的判斷：審查深度跟著風險走

  • 一次性、可丟棄的工具：先確認輸入、輸出與失敗行為。
  • 會持續維護的產品功能：閱讀 diff、介面、邊界與錯誤處理。
  • 涉及權限、金流、隱私、安全的關鍵路徑：仍由人直接閱讀並留下驗證證據。

真正的問題不是「有沒有讀每一行」，而是如果它錯了，誰承擔後果？我們又憑什麼相信它是對的？

Code Review 正在改變

當 AI 產出的速度遠超過人的閱讀速度，單靠逐行審查無法無限擴張。未來的 Review 需要同時包含需求品質、測試證據、風險分級、觀測能力與人工抽查。不是放棄理解，而是把有限的注意力放到最值得理解的地方。
