真正遺失的，不只是聊天紀錄

換專案後最痛的不是 AI 忘了你的名字，而是它忘了你怎麼做判斷、為什麼這樣決定，以及哪些方法已經被驗證過。

Session Memory

聊天視窗記得

同一段對話裡很方便，但視窗結束、內容過長或換專案後，重要脈絡可能不再出現。

Project Memory

單一專案記得

AGENTS.md、CLAUDE.md 或專案設定能保存局部規則，但另一個專案不一定會讀到。

External Brain

你自己的大腦記得

知識放在獨立資料夾，由你管理。不同 AI 只要取得授權，就能查詢同一份長期記憶。

一句話理解：AI 工具像不同的工作夥伴；外部大腦則是大家共同查閱、而且由你擁有的工作手冊。

Second Brain 不是一個神奇 App

它其實是四個簡單組件。先分清楚各自職責，就不會把資料夾、Wiki、MCP 和網頁混成同一件事。

1. 儲存庫

真正保存 Markdown、附件、決策與 Skill 的地方。可以是一個本機資料夾或私人同步空間。

2. 管理者

Wiki Agent 或指定的 AI 負責整理、去重、補來源、標狀態，不讓正式知識被隨意改壞。

3. 連接器

Skill、CLI 或 MCP 告訴不同 AI 怎麼查、怎麼送出待保存內容。MCP 像接頭，不是硬碟。

4. 可視化介面

HTML 或 Dashboard 讓人看得到收件匣、正式知識、關聯與搜尋結果，但它不是唯一的資料來源。

知識從進來到被找回的五步驟

不要讓 AI 看到一句話就直接改正式 Wiki。保留來源、經過審核、建立索引，才有可長期信任的記憶。

1
Capture

收進筆記、對話摘要、專案結論、網址、文件與可重複工作方法。

2
Review

先放 raw / inbox，檢查來源、敏感資訊、重複內容與是否真的值得長期保存。

3
Organize

整理成個人偏好、專案、知識、決策、Skill、人物或來源等清楚分類。

4
Index

建立關鍵詞、標籤與關聯索引，讓搜尋不用把全部檔案一次塞給模型。

5
Recall

AI 先查大腦、引用少量相關來源，再回答問題或協助執行下一步。

建議的資料夾分法

第一版不需要複雜資料庫。Markdown 加上清楚狀態就能開始；未整理與正式知識要分開。

ai-brain/
├─ raw/                 # 原始來源，不改寫
│  └─ sessions/         # 值得保存的對話摘要
├─ inbox/               # 等待審核的候選知識
├─ wiki/                # 已審核、可查詢的正式知識
│  ├─ profile/          # 個人背景與偏好
│  ├─ projects/         # 專案目標與狀態
│  ├─ knowledge/        # 主題知識與方法
│  ├─ decisions/        # 決策、理由與結果
│  ├─ skills/           # 可重複使用的流程
│  ├─ people/           # 人物與協作脈絡
│  ├─ sources/          # 來源與引用
│  └─ archive/          # 過期但保留的內容
└─ index/               # 搜尋與關聯索引

raw/

保存原始證據。即使整理錯了，仍能回頭核對真正來源。

inbox/

AI 可以送提案進來，但還不能當成正式真相。

wiki/

經過整理與審核後，才成為其他 AI 可以優先引用的長期知識。

index/

保存搜尋索引與關聯。它可以重建，不應取代原始 Markdown。

不同 AI、不同裝置怎麼共用

核心原則不是複製很多份大腦，而是讓每個入口都連回同一個受控來源。

主要電腦直接讀本機資料夾，速度最快。
其他電腦使用私人同步、副本或受保護的遠端連線。
手機透過受控 Bot 或網頁提交問題與待保存內容。
唯一的大腦 Markdown + Wiki + Index
Codex透過 Skill、CLI 或 MCP 查詢與送出提案。
Claude Code讀共同 Skill，連到同一份知識來源。
其他 Agent只要支援檔案、指令或 MCP，就能接入。
同一臺電腦

本機 MCP / CLI

適合直接查詢。資料不必經過公開網路，權限範圍也比較容易控制。

其他電腦

私人同步或遠端 MCP

私人同步較簡單；遠端 MCP 較即時，但必須加入身分驗證、加密與存取紀錄。

看得見

HTML Dashboard

用來搜尋、檢查狀態與查看關聯。即使介面壞了，底層知識檔仍然存在。

好用 AI 大腦的六個驗收能力

不是檔案很多就叫大腦。真正好用的標準，是能準確找回、誠實面對未知、受控保存，並跨入口使用。

1

精準查到

找到少量真正相關內容，並標出來源，而不是把整個資料夾全部塞進上下文。

2

找不到就說沒有

沒有證據時不補故事。未知要明確標示，讓使用者決定是否新增資料。

3

可以要求保存

使用者能用自然語言說「記到大腦」，內容先成為待審核提案。

4

自動找出關聯

新知識能連到既有專案、決策、人物或 Skill，慢慢形成可探索的知識網。

5

主動提醒重點

討論出穩定決策或新方法時，AI 可以建議保存，但要等使用者同意。

6

跨工具與裝置

記憶不綁定單一聊天視窗、單一 AI 或單一專案，授權後可從不同入口取用。

先把邊界做好，才值得長期信任

大腦會累積非常多個人脈絡；權限、審核、備份與刪除能力，跟搜尋速度同樣重要。

應該做

建立可回復、可審核的流程

  • 原始來源先保留，正式 Wiki 與待審核內容分開。
  • 每筆內容記錄來源、日期、狀態與最後更新時間。
  • 備份加密，其他裝置只取得完成任務所需的最低權限。
  • 定期測試搜尋結果，移除重複或過期內容。
不要做

避免把大腦變成新的風險中心

  • 不要保存密碼、Token、Cookie、私密金鑰或環境變數。
  • 不要讓每個 Agent 都能直接改寫正式知識。
  • 不要把整個資料夾公開到沒有驗證的網路端點。
  • 不要因為圖形介面看起來很完整，就忽略來源與錯誤。
兩個現實限制：第一，只有關鍵詞搜尋時，同義詞可能漏找，之後可再加入本機語義搜尋；第二，系統不會憑空長大，重要討論仍要養成主動保存與定期整理的習慣。

從簡單版本開始的三階段

先讓一臺電腦上的一個 Agent 能安全查詢，再擴到其他 Agent 和其他裝置。每一階段都要能獨立驗證。

PHASE 01

一個資料夾

建立 raw、inbox、wiki、index。先收個人偏好、專案決策與三個最常用 Skill。

PHASE 02

多個 AI 共用

為 Codex、Claude Code 與其他 Agent 安裝相同的「大腦」Skill，統一查詢與保存語句。

PHASE 03

其他裝置安全接入

選擇私人同步或受保護的遠端 MCP，再加入加密、驗證、最低權限與稽核紀錄。

不必背指令，直接這樣說

同一套操作語言可以放進每個 Agent 的 Skill，讓使用者不需要記得底層工具差異。

先查再回答

先查大腦，再回答這個問題。請只引用最相關的來源；如果大腦裡沒有資料，請直接說沒有找到，不要自行補充。

保存新決策

記到大腦：把剛才確認的決策、理由、適用範圍與待辦事項整理成候選知識。先放入待審核區，不要直接改正式 Wiki。

找出可重複方法

整理大腦：檢查最近的專案紀錄，找出可以重複使用的 know-how。請區分一般知識、決策與可做成 Skill 的流程。

檢查大腦品質

大腦狀態：列出待審核數量、正式知識數量、重複或矛盾內容，以及最需要補來源的三個項目。

來源與審核備註

本頁以「使用者擁有一份外部知識來源，讓多個 AI 受控取用」為主軸，並加入知識審核、權限與可回復性設計。
