問題：同一條規則，不該每次重新交代

在不同任務或不同 AI 工具之間切換時，已確認的規則容易留在各自的聊天紀錄裡。使用者需要反覆交代背景，也難以判斷 AI 引用的是已確認的決策，還是尚未驗證的建議。

這個個人實作把長期知識放在對話之外。Agent 執行前先查相關資料；值得保留的新發現先成為候選知識，由人審核後才進入正式來源。

設計範圍與選擇

  • 一份共用來源：由使用者管理知識，不必為每個聊天視窗重新複製背景。
  • 三種資料狀態：原始資料保留依據，候選區收集新提案，正式區只放已審核知識。
  • 受控的讀取與更新：透過一致的查詢入口找少量相關資料；查詢權限與更新權限分開考慮。
  • 人工確認：資料有矛盾、缺少來源或涉及敏感內容時，保留人工決定的位置。

這些設計取自本站的跨 Agent 共用記憶實作教學，公開內容呈現方法與資料流，不包含私人資料庫或內部紀錄。

流程示範：完成一份可檢查的週報摘要

以下是用虛構資料重建的說明情境，不是實際客戶對話或產品執行紀錄。

輸入任務

「幫我整理本週待辦摘要。沿用先前確認的格式，完成後先給我檢查。」

已確認的規則

摘要包含「已完成、待確認、下一步」三部分；沒有依據的事項列為待確認，不當作已完成。

預期輸出

一份依照既有格式整理的摘要，附上採用的規則來源，以及缺少依據的項目。這裡展示的是流程與輸出規格，不是連線執行中的 Agent。

  1. 查找相關規則
    找出摘要格式與適用範圍。沒有找到時先說明缺漏，不自行聲稱已存在某項規定。
  2. 產生待確認成果
    依規則整理內容，分開列出有依據的結果與待確認事項。
  3. 提交候選知識
    若使用者希望下次新增「負責人」欄位，先記為候選更新，附上來源、日期與適用範圍。
  4. 人工審核後再沿用
    確認這是長期規則後才更新正式知識。下一次執行再查正式版本；未核准內容不視為既定規則。

成果與驗收：要能檢查每次引用的依據

這個案例可公開呈現的成果，是一套將查詢、候選提交與人工審核分開的個人工作流，以及可閱讀的實作教學。沒有公開節省工時、正確率或客戶營運成效數據。

導入時使用的驗收清單

  • 找得到資料：給定一項已知規則，能找到對應內容並指出來源。
  • 找不到就說明：沒有相關資料時，回報缺漏，不捏造過去決策。
  • 候選內容不直接生效：新提案仍停在待審核狀態時，不作為正式規則引用。
  • 衝突可交回人處理：新舊說法不一致時，列出來源差異並等待確認。
  • 更新可以追查：保留來源、日期與狀態，方便核對此次採用的版本。

這份清單是試做與驗收的依據，不代表所有導入情境都已通過測試。合作時會以雙方同意的測試資料逐項驗收。

適用情境與限制

適合需要重複沿用規則、工作方法或專案決策的情境，例如週報整理、作業說明查找與專案交接。第一步應選定一類工作和少量可用資料，再確認由誰審核更新。

資料品質、存取權限、過期內容與審核負擔仍需要管理。共用知識庫不保證 AI 每次回答正確；重要結果仍須核對原始來源。私人知識庫也不因這篇案例而對外開放。

AI Agent 知識庫常見問題

這和把文件貼進聊天視窗有什麼不同？

文件貼進對話可提供當次背景；這個案例另外管理長期來源、候選與正式狀態，讓後續任務可以重新查詢已確認的知識。

需要重新訓練 AI 模型嗎？

這個案例採用外部知識查詢與工作流程設計，不以重新訓練模型為前提。工具與模型仍需依資料、權限和任務需求選擇。

可以讓不同 Agent 共用嗎？

可以設計共用入口，但各工具都必須具備適當權限和連接方式。共用來源不等於把所有資料交給每一個工具。

能先做一小部分再決定是否擴大嗎？

可以先選一類任務，確認輸入、預期輸出、人工審核點與驗收方式，再評估是否擴大。查看AI Agent 導入服務與合作方式。

想做類似的知識庫？先準備這五項資訊

初次討論可用概述或去識別的例子，不需先提供完整文件或私人資料。

  1. 想改善的工作：例如找作業規則、整理週報或交接專案背景。
  2. 現在的資料：大致有哪些文件、格式與數量？誰能使用？
  3. 預期成果：希望得到附來源的回答、摘要，或一份待確認清單？
  4. 確認方式：由誰判斷結果正確、哪些動作必須先得到同意？
  5. 範圍與時間：想先試做哪一小部分？是否有預算或時間限制？

首次 30 分鐘需求討論不收費。討論後再確認試做範圍、交付內容與報價；公開案例不代表所有需求都能直接套用。

下一步：評估你的工作情境

洽談時提供一項想改善的工作、目前資料來源，以及希望交付的結果即可。第一次討論先確認資料範圍與試做目標；任何實作範圍、費用與完成條件都在動工前確認。
