Reading path 01

AI Agent 實作與學習AI practice notes

從模型、工作流、工具實驗到安全檢查，依真實實作紀錄繼續閱讀。

  1. AI 會改變世界，但我們真的知道它會變成什麼樣嗎？從 Ilya Sutskever 與 Yoshua Bengio 的觀點，思考 AI 未來的不確定性，以及保留修正想法的能力。
  2. Agent 能檢查線路圖，那 PCB layout 呢？從 Adom 的 Astra PCB layout 示範，思考工程師如何 review AI 提出的元件擺放與佈線方案。
  3. 模型一直在換，但你的流程要站得住新模型來得很快；真正可以累積的，是量測任務、設定權限邊界與驗收結果的工作方法。
  4. API Key 不是設定，是權限一次事件後的 30 分鐘 API Key 安全盤點：找出憑證、輪替有疑慮的 key，並設好上限與通知。
  5. 讓規則真的發生：Claude Code 與 Codex HooksHook 把反覆提醒 Agent 的工作，改成固定時機、固定範圍、固定回應的工作規則。
  6. 下一代 AI 裝置，應該是一個能持續生長的平台AI 眼鏡、手錶與智慧家電的競爭，不只在硬體與內建功能，也在它是否能讓開發者與使用者持續擴充。
  7. 訊息整合 App把分散訊息集中處理，同時保留人工確認。
  8. 私人訊息中繼站把跨平台訊息放回同一個工作脈絡。
  9. AI Code 審查深度AI 產生的程式碼，審查深度應跟著風險調整。
  10. 用語音 Brief Agent從寫 Prompt 到用語音整理 Agent Context。
  11. AI Agent 協助線路圖檢查讓 AI Agent 先處理線路圖重複檢查，再由 EE 判斷。
  12. 把學習整理成一個公開入口我想做的不是另一個資訊列表，而是把散落的 AI Agent 資料整理成能理解、比較，也能真正動手做的入口。
  13. One Brain, Many Agents換一個 AI 工具，不應該等於重新介紹自己；記憶應該跟著人，而不是跟著聊天視窗消失。
  14. 下一代 RAG，不只是更多 Chunks大型知識庫搜尋不該只找到看起來相似的段落，而要能沿著文件結構找到真正相關的頁面與證據。
  15. 高價值的 RD 時間，不該消耗在料號、BOM 和 ECN保留既有 PLM，讓受控的 AI Agent 處理料號、BOM 與工程變更流程，減少 RD 的重複系統操作。

Reading path 02

工程思維與工作方法Engineering and work methods

從系統工程、可靠性、專案取捨到工作溝通，看看這些方法如何形成 AI 實作的底層判斷。

  1. 工程設計與採購現實的三角平衡最低報價不一定能製造；如果設計、價格與時效沒有一起看，工程與採購都會被流程卡住。
  2. 把 IPC 測試指令整理成一個工具箱好的測試工具會把散落指令變成一鍵執行、選單與 API，讓驗證從記憶工作變成可靠流程。
  3. 把複雜需求拆成可執行的 DFMEADFMEA 不只是填表，而是從客戶需求、系統邊界與功能結構，走到風險與驗證計畫的共同語言。
  4. 帶纜線防水裝置的設計思考防水不是多加一個密封圈，而是讓外殼接面、溝槽、壓縮量與纜線通道共同形成可靠界面。
  5. 團隊的每個小成就，都值得被看見困難工作裡，真誠而具體的鼓勵不是裝飾，而是讓團隊願意繼續往前的推進力。
  6. 專案管理裡，不可能同時最大化一切預算、時程與範圍之間永遠存在限制；成熟的管理不是假裝沒有取捨，而是把取捨變成明確決策。
  7. 專業被質疑時，先把對話帶回證據冷靜、事實、傾聽與可執行方案，比立刻防衛更能建立信任，也更容易讓對話繼續。
  8. 系統工程師看的，不只是硬體規格一個工業電腦系統能不能長期成立，取決於需求、架構、風險、可靠性、散熱、成本、生產與維護是否被一起考慮。
